# Invoice Agent

Локальный прототип для преобразования российских счетов на оплату из PDF,
JPG и PNG в проверяемый структурированный реестр с экспортом в CSV/XLSX.

> Проект не оплачивает счета и не принимает бухгалтерских решений. Любой
> распознанный документ должен быть проверен человеком по оригиналу.

## Для чего нужен проект

Invoice Agent сокращает ручной перенос реквизитов из входящих счетов в таблицы.
Он подходит для демонстрации сценария снабжения, бухгалтерии или внутреннего
документооборота:

1. пользователь загружает один или несколько счетов;
2. сервис извлекает текст из PDF либо запускает локальный OCR для скана;
3. детерминированный экстрактор формирует карточку счета;
4. пользователь сверяет и исправляет результат;
5. подтвержденные данные выгружаются в CSV или XLSX.

Извлекаются:

- поставщик и покупатель, ИНН и КПП;
- банк, БИК и расчетный счет поставщика;
- номер и дата счета, договор и срок оплаты;
- сумма без НДС, ставка и сумма НДС, итог;
- товарные позиции, количество, цена и сумма строки;
- предупреждения и уверенность по отдельным полям.

## Возможности

- текстовые и сканированные PDF;
- фотографии JPG/PNG;
- локальный OCR на русском и английском языках;
- пакет до 20 документов;
- просмотр оригинала рядом с карточкой;
- ручное редактирование реквизитов и товарных позиций;
- проверка ИНН, КПП, БИК, счета и итоговых сумм;
- экспорт реестра и товарных позиций в XLSX;
- CSV-экспорт;
- локальная обработка без отправки документа во внешний AI API.

## Архитектура

```text
Браузер
   ↓
Fastify + TypeScript
   ↓ запуск без shell, с тайм-аутом
Python bridge
   ↓
PDF text / EasyOCR
   ↓
Детерминированный экстрактор
   ↓
Проверка человеком → CSV/XLSX
```

Основной сервер написан на TypeScript. Python отвечает за PDF, OCR, извлечение
полей и экспорт. Старый `web_server.py` оставлен только как локальный резервный
вариант и не рекомендуется для развертывания.

## Требования

- Node.js 24 или новее;
- Python 3.12;
- Windows, Linux или macOS;
- несколько гигабайт свободного места для OCR-моделей и зависимостей.

## Установка

```powershell
git clone https://github.com/Kopilainenen/invoice-agent.git
cd invoice-agent

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt

npm ci
npm run build
```

Для Linux/macOS активация окружения:

```bash
source .venv/bin/activate
```

EasyOCR может загрузить модели при первом распознавании. Они хранятся локально
и не должны добавляться в Git.

## Запуск веб-интерфейса

```powershell
npm start
```

Откройте `http://127.0.0.1:8765`.

По умолчанию сервер слушает только loopback-интерфейс и недоступен другим
компьютерам сети.

## Запуск из командной строки

Извлечь один документ:

```powershell
python run_extract.py output/pdf/dea_test_invoice.pdf --output result.json
```

Обработать несколько документов:

```powershell
python run_batch.py documents --output-dir batch-results
```

Синтетический тестовый счет D.E.A. можно пересоздать:

```powershell
python scripts/generate_dea_test_invoice.py
```

Все реквизиты тестового документа вымышлены и предназначены только для
разработки и демонстрации.

## Проверки перед изменениями

```powershell
python -m unittest discover -s tests -v
npm run typecheck
npm run build
npm run audit:prod
```

Тесты проверяют извлечение реквизитов и позиций, уверенность важных полей,
CSV/XLSX-экспорт и наличие основных элементов интерфейса.

## Безопасность

TypeScript-сервер:

- проверяет расширение, MIME и сигнатуру файла;
- ограничивает размер, количество загрузок и частоту запросов;
- применяет CSP и защитные HTTP-заголовки;
- валидирует экспортируемый JSON через Zod;
- запускает Python без командной оболочки;
- ограничивает время работы дочернего процесса;
- удаляет временный загруженный файл после обработки;
- скрывает cookie и Authorization из логов.

Это локальный MVP. Не публикуйте порт напрямую в Интернет. Для коммерческого
развертывания нужны авторизация, TLS, reverse proxy, изолированный контейнер,
антивирусная проверка, отдельное хранилище и политика удаления документов.
Подробнее: [SECURITY.md](SECURITY.md).

## Ограничения

- экстрактор ориентирован на российские счета на оплату;
- качество OCR зависит от разрешения, наклона и освещения;
- шаблоны разных поставщиков требуют расширения тестовой выборки;
- отсутствующее поле возвращается пустым, а не придумывается;
- проект не выполняет юридическую или бухгалтерскую проверку;
- договоры, акты, накладные и автоматическая оплата не поддерживаются.

## Структура

```text
server/                 TypeScript/Fastify backend
web/                    браузерный интерфейс
src/invoice_agent/      Python-экстрактор и экспорт
scripts/                bridge и генератор тестового счета
schema/                 JSON Schema карточки
tests/                  автоматические тесты
fixtures/expected/      эталон синтетического документа
output/pdf/             синтетический PDF для тестов
```

## Статус

Это портфолио/MVP, а не готовый SaaS. Следующие практические этапы: независимая
оценочная выборка документов, метрики по каждому полю, аутентификация,
изолированное развертывание и политика хранения.
